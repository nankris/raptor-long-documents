Use a fresh Python-capable Colab L4. `source /workspace/tools/setup.sh`; check `colab usage` >=50 CU, create only your named session, and set a watchdog based on its billing rate. This experiment used r3074.

1. Execute init.py with `colab exec -s r3074 --timeout 900 -f scripts/init.py`. This installs packages, downloads the public validation dataset/model, and leaves model and functions resident in the remote kernel.
2. Run `bash scripts/control.sh`. It invokes step.py for ONE article then downloads and extracts the checkpoint locally before starting the next article. It stops its session on completion or failure. Invoke it inside a hard timeout as in the experiment: `timeout --signal=TERM 9600 bash scripts/control.sh`. watchdog.py provides an additional independent cap; account for setup time and GPU rate.
3. To resume on the SAME runtime, rerun control.sh; completed article IDs are skipped. On a NEW runtime, upload results/checkpoint.tar.gz to /content/checkpoint.tar.gz, execute restore.py, then init.py and control.sh. Trees and stored node embeddings are reused. Query embeddings are inexpensive and recomputed. Partial article output is never committed. Never silently switch GPU, reader, thresholds or sample based on observed accuracy.
4. After stopping GPU, use local Python with numpy/scipy/matplotlib: `python scripts/audit.py`; `python scripts/analyze.py`. The latter implements the fixed decision rule and chart. Read results/statistics.json and results/audit.json. Full paired output includes question, options, gold, letter logits, contexts and selected levels. Trees contain the original leaf text and all generated summaries; embeddings are .npy arrays aligned to node order.

The checkpoint archive is ignored by git because its extracted contents are committed; reconstruct with `tar czf results/checkpoint.tar.gz -C results checkpoint`. Metadata contains dataset fingerprint and model commit. Package install pins transformers 4.57.6; other versions are logged in metadata where relevant. Qwen3 thinking is disabled for both summarization and answering. A/B/C/D predictions are constrained by next-token logits, with gold used only after inference for scoring.

Final execution uses the more robust `worker.py` and `worker_control.py` instead of repeated step.py calls. After init.py, execute worker.py once (it starts a resident background thread), then run worker_control.py locally with Colab CLI available in PATH. The worker waits for /content/batch_ack.json after EVERY article; the controller sends that acknowledgement only after downloading, validating and extracting the checkpoint. It retries transient file-transport failures and stops the GPU in finally. After a replacement runtime, restore the archive first, initialize, launch worker.py, then controller. Use the final worker's token-limited summary scheduler; init.py contains the earlier safe two-prompt implementation but worker.py overrides it before any new tree is built.
